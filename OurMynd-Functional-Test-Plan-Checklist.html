21. Reporting and blocking not yet built

21.1Report another participant from inside a focus roomFAILNone of section 21 exists. There is no moderation route in server/src/routes, no reports, blocks, strikes or moderation-actions tables, no report control on any surface, and no admin queue. Blocking is therefore not enforced in feed, social, chat or matchmaking queries either.

This is the single largest gap in the build. Apple Guideline 1.2 requires all of it before a user-generated-content app is approved, and Terms section 6 already tells users these tools exist. It is a feature to be built, not a defect to be fixed — roughly a moderation route with four tables and migrations, a reason-picker report flow on posts, messages, room participants and profiles, server-side block enforcement in every query that returns another user, a strike counter with automatic suspension, and an admin view or CLI so the published 24-hour review commitment can actually be met.

21.9 additionally depends on the age-declaration work: no date of birth is collected at sign-up and there is no is_minor flag, so minors cannot be excluded from adult matchmaking.
